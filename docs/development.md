# Разработка: правила и устройство проекта

Документ для участников команды. Прочитайте его перед первым изменением — здесь то, что легко сломать незаметно.

## Обязательные правила

1. **Статус заявки меняется только через `transition()`**
   ([`backend/app/services/state_machine.py`](../backend/app/services/state_machine.py)). Там таблица разрешённых
   переходов, проверка роли, запись в `status_history` и уведомления. Недопустимый переход — HTTP 409.
   Никаких `application.status = ...` в других местах (единственное исключение — создание черновика).
   Новый переход = новая строка в `ALLOWED_TRANSITIONS` + тест.
2. **Проверка владельца на каждом клиентском запросе к заявке** — через `get_owned_application()`
   ([`backend/app/deps.py`](../backend/app/deps.py)). Чужая заявка — 403.
3. **Веса, пороги скоринга, таблица решений и надбавки к ставке — только в
   [`backend/scoring_config.yaml`](../backend/scoring_config.yaml).** Поменяли цифры — поменяйте `model_version`
   и прогоните `tests/test_pipeline.py`: демо-сценарии должны давать прежние классы.
4. **Тексты интерфейса — на русском и простым языком.** Банковские термины — только через `<Term k="…">`
   ([`frontend/src/lib/glossary.tsx`](../frontend/src/lib/glossary.tsx)). Ошибки — человеческие
   («ИНН должен быть из 10 или 12 цифр»). На каждом статусе клиент видит: что происходит, сколько ждать,
   нужно ли что-то от него (`backend/app/services/next_action.py`).
5. **Только синтетические данные.** Никаких email/SMS — уведомления только в кабинете. Без логотипов и названий
   реальных банков; продукт называется «Оборот».
6. **Только бесплатные open-source зависимости.** Новую библиотеку — добавить в
   [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) с лицензией.
7. **API меняется вместе с типами фронта:** после изменения схем —
   `uv run python -m app.export_openapi` и `npm run gen:api`, оба файла коммитятся.
8. **Ключевые места кода комментируются по-русски** (state machine, скоринг, воркер, опрос статуса на фронте) —
   проект защищают перед жюри.

## Стек

- **Бэкенд:** Python 3.12, FastAPI, SQLAlchemy 2 (синхронный), Alembic, Pydantic v2, PostgreSQL 16, uv, pytest.
- **Фронтенд:** Vite, React 19, TypeScript, React Router, TanStack Query, react-hook-form + zod, Mantine 9.
- **Инфраструктура:** Docker Compose, nginx (раздаёт фронт и проксирует `/api`).

  services/

    stats.py            аналитика конвейера

backend/tests/          pytest; демо-сценарии — tests/scenarios.py
mock-external/          ЕГРЮЛ, ФНС, БКИ, счёт в банке; данные — app/data/companies.json
frontend/src/
  api/                  client.ts, queries.ts (все запросы), schema.d.ts (сгенерирован)
  pages/                экраны клиента; pages/analyst — кабинет специалиста

## Команды

```bash
docker compose up --build                                  # весь стенд, http://localhost:3000
docker compose up -d db && cd backend && uv run pytest     # тесты бэкенда (БД oborot_test создаётся сама)
cd backend && uv run alembic revision --autogenerate -m "…" # миграция после изменения models.py
cd backend && uv run python -m app.export_openapi          # docs/openapi.json
cd frontend && npm run gen:api                             # типы фронта из docs/openapi.json
cd frontend && npm run typecheck                           # проверка типов
cd frontend && npm run dev                                 # фронт с горячей перезагрузкой (API — из docker на :8000)
```

## Как устроено то, что легко сломать

- **Очередь задач** — таблица `jobs`, `SELECT … FOR UPDATE SKIP LOCKED`, «аренда» задачи 30 с с продлением перед
  каждым этапом. Этап конвейера должен укладываться в аренду: при увеличении таймаутов внешних сервисов увеличьте
  `JOB_LEASE_SECONDS`.
- **Каждый этап конвейера — своя транзакция** с блокировкой заявки; сетевые запросы — вне транзакции.
  Конвейер возобновляется с текущего статуса, поэтому этапы должны быть повторяемыми.
- **Недоступный внешний сервис** (после 3 попыток) отправляет заявку к специалисту; недоступность данных счёта
  в банке — нет (это внутренние данные).
- **Предодобренный лимит считается тем же `score()`, что и заявки** — меняя скоринг, проверьте
  `tests/test_ecosystem.py`.
- **Тесты не ходят в сеть:** `tests/conftest.py` подменяет `external.fetch` данными мок-сервиса.

## Интерфейс

- Цвета, скругления, шрифт — только в `theme.ts` и `global.css`; на экранах цвета руками не задаём.
- Красный акцент `#EF3124`, графитовый текст `#0B1F35`, фон `#F3F4F5`, белые карточки без рамок.
- Каждый экран показывает загрузку, пустое состояние и ошибку (`components/StateViews.tsx`).
- Вёрстка: десктоп от 1280 px и телефоны от 375 px. На телефоне — нижняя панель вкладок, окна во весь экран,
  широкие таблицы — карточками. Проверка: на ширине 375 px у страницы не должно быть горизонтальной прокрутки.
- Редкие экраны грузятся лениво (`lazy()` в `App.tsx`), библиотеки — отдельными файлами (`vite.config.ts`).

## Git

- Коммит после каждого законченного шага, сообщения на английском: `feat:`, `fix:`, `chore:`, `docs:`, `test:`, `perf:`.
- Перед коммитом: `uv run pytest` и `npm run typecheck`.
- Перед демо: `docker compose down -v && docker compose up --build` — чистая база с демо-данными.
