# Сценарий демо (5–7 минут)

Главная мысль, которую должно унести жюри: **простые заявки решаются сами за минуту, сложные приходят
специалисту с готовыми данными, а клиент на каждом шаге понимает, что происходит.**

## Подготовка (за 15 минут до выхода)

```bash
docker compose down -v && docker compose up --build -d
```

1. Дождаться, пока `docker compose ps` покажет `healthy` у api, db, mock-external.
2. Открыть **два окна браузера с разными профилями** (или обычное + инкогнито) — cookie входа у каждого свои:
   - окно «Клиент» — `client1@demo.local`;
   - окно «Специалист» — `analyst@demo.local`.
3. Открыть терминал в папке проекта, шрифт покрупнее.
4. Заранее подготовить (чтобы не тратить время на сцене):
   - **«Вектор-Тест»** (сценарий 3): отправить заявку, загрузить любой PDF как выписку — заявка будет ждать специалиста;
   - **«Закат-Тест»** (сценарий 4): отправить — будет отказ;
   - **черновик ИП «Тестов»** (сценарий 2) как `client2` или `client1`: заполнить до шага «Отправка», но не отправлять.
5. Масштаб браузера 110–125%, закрыть лишние вкладки, выключить уведомления системы.

Цифры для всех заявок — в [scenarios.md](scenarios.md).

## Ход демо

| Время | Что говорим | Что показываем |
|---|---|---|
| **0:00–0:30** | «Предприниматель берёт кредит редко и без подготовки. Непонятно, что выбрать, что писать в анкете, а после отправки заявка пропадает. Мы сделали конвейер, где простые заявки решаются за минуту, а клиент всегда видит, что происходит». | Экран входа, подсказка с тестовыми аккаунтами |
| **0:30–0:50** | «Мы — банк клиента и уже видим обороты по его счёту. Поэтому лимит — до заявки и без документов». | Главная `client1`: галочка → «Рассчитать лимиты» → баннер «до 15 000 000 ₽», таблица лимитов по компаниям, «Подробнее» у «Ромашки» — из чего сложился лимит и как увеличить |
| **0:50–1:20** | «Если клиент не знает, что выбрать — три вопроса». | Окно «Клиент» → «Получить финансирование» → «Срочно закрыть разрыв», 2 млн, 12 мес → рекомендация с платежом и альтернативами. Навести на «равными частями» — подсказка |
| **1:20–2:10** | «ИНН — и банк сам подтягивает данные компании, а выручку — из оборотов по счёту. Каждое поле с подсказкой, черновик сохраняется сам». | ИНН `0010000017` → карточка компании → финансы: выручка уже подставлена (зелёная плашка) → платежи 50 000, сотрудников 12 → «Черновик сохранён» → галочка → «Отправить» |
| **2:10–2:50** | «Смотрите на ленту слева — заявка сама проходит проверки в реестре, налоговой и бюро. Справа всегда ответ: что происходит, сколько ждать, нужно ли что-то от меня». | Статус движется: Проверка → Оценка → «Заявка одобрена», причины. «График платежей» и «Условия кредита» (ПСК) → «Принять» → код на экране → ввести → **«Деньги зачислены»**, ближайший платёж |
| **2:50–3:50** | «Надёжность. Остановим обработчик заявок — как будто сервер упал». | Терминал: `docker compose stop worker`. Окно «Клиент»: открыть черновик ИП «Тестов» → «Отправить» → статус стоит на «Отправлена». Терминал: `docker compose start worker` → через несколько секунд заявка пошла дальше сама. «Заявка и задача сохраняются в одной транзакции — потерять её нельзя» |
| **3:50–4:20** | «Не одобрили всю сумму — но не отказ, а понятное предложение». | Результат «Тестова»: «Вы просили 2 000 000 / Мы предлагаем 1 400 000», причина — просрочка 15 дней |
| **4:20–5:40** | «Теперь сторона банка. Специалист видит только то, что ждёт его решения». | Окно «Специалист»: очередь «Ждут меня», классы риска → открыть «Вектор-Тест»: проверки цветными плашками, скоринг по факторам (+15 / −20), выписка, рекомендация «Одобрить меньшую сумму» → «Подставить в решение» → комментарий → «Одобрить с новыми условиями» |
| **5:30–5:40** | «И главное для банка — сколько система решает сама». | Окно «Специалист» → «Аналитика»: доля решений без специалиста, первый ответ клиенту за секунды, воронка |
| **5:40–6:00** | «Клиент видит решение сразу, без звонков». | Окно «Клиент» → заявка «Вектора»: «Мы предлагаем 7 000 000», причина — комментарий специалиста |
| **6:00–6:30** | «Если отказ — объясняем почему и что делать». | Заявка «Закат-Тест»: причина про ликвидацию, совет, «Подать заново» |
| **6:30–7:00** | «Всё запускается одной командой, внешние сервисы — мок с тем же контрактом, 131 автотестов. Правила скоринга — в конфиге, каждое решение объяснимо». | Слайд с архитектурой (схема из README) |

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Статус не двигается | `docker compose ps` — воркер запущен? `docker compose start worker`. Пока ждём — рассказать про очередь |
| Страница не открывается | `docker compose up -d`; в запасе — скриншоты ключевых экранов |
| Забыли пароль | на экране входа нажать на email — подставится сам |
| Нужно быстро показать отказ | «Новичок-Тест» уже есть у `client2` (заявка из seed) |
| Нужно показать недоступный внешний сервис | ИНН `0010000056` — БКИ не отвечает, через ~15 с заявка у специалиста; карточка показывает красную плашку БКИ |
